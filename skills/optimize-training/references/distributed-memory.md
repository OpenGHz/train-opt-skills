# 分布式通信与显存预算

在通信暴露、rank 等待、显存不足或重计算代价大时使用本页。
单卡任务跳过分布式；没有显存约束时不为了使用 FSDP 而引入分片。

## 确认约束与版本

记录 DP/TP/PP 拓扑、实际框架版本、FSDP 类型、封装层和 checkpoint 协议。
检查用户配置是否真正映射到后端，是否被忽略或回退。
FSDP1 包装器参数和 FSDP2 模块方法不能互换，不能跨版本照搬配置。
对 FSDP2 核对优化器初始化是否引用分片后的参数，正常调用模块以触发前向钩子。
先验证基线的梯度归约、损失缩放、累积边界、各 rank 参数和恢复行为。

## 把通信问题分解为假设

| 时间线证据 | 下一步 |
| --- | --- |
| 部分 rank 很晚进入同一通信 | 查取数、序列长度、分支、日志/保存及负载差异 |
| 频繁小通信且调用成本明显 | 试更合适的分组，检查总更新耗时 |
| 大量通信活动但很少暴露等待 | 不凭活动占比判断主瓶颈 |
| 后续计算明确等待参数 | 检查分组边界、发起时机和可用预取 |
| 预取后峰值显存显著上涨 | 减少同时存活参数或重新分配预算 |

区分通信活动并集、与计算交集和关键路径暴露等待，不能简单相加多流时长。
所有 rank 等待落后者不等于网络带宽不足；先修复上游不均衡。

## 分片与预取联合实验

1. 保留当前合法配置作为基线并保存时间线。
2. 以单重复块或相邻块为候选通信组，检查真实执行顺序。
3. 比较每组计算、调用数量、参数存活时间和总更新耗时。
4. 在合法边界上评估框架已有重叠，再试额外预取。
5. 将分组和预取作为有依赖的组合，测显存峰值与端到端收益。
6. 完成分布式数值、质量和断点恢复回归后保留配置。

FSDP2 的 `fully_shard` 边界影响通信分组；按层组织可创造重叠机会，不保证收益。
不同模块可以不同粒度；更细分组和更深预取都不是目标本身。
无收益时回到执行顺序和成本证据，不继续无依据地叠加环境变量。

## 显存账本

| 指标 | 用途与限制 |
| --- | --- |
| allocated | PyTorch 活跃张量所占内存 |
| reserved | 分配器向设备保留的内存，包含缓存 |
| 设备级占用 | 还可能包含通信库和非 PyTorch 分配 |
| 内存快照 | 判断分配模式、生命周期和疑似碎片 |

`reserved - allocated` 不能全部叫碎片；设备监控的单值也不能解释来源。
分别记录前向、反向、更新、验证、保存与代表性长输入的峰值。
内存快照无法覆盖所有外部分配，需和设备级占用交叉解释。
`expandable_segments` 等分配器项针对特定模式，按版本、平台和 allocator 支持核对。
不要默认定期清缓存，先证明问题来自何种分配行为。

## 按模块标定激活重计算

记录实际重计算边界，而不是只写项目含义不明的 `stride`。
为显存开销大、重算昂贵的模块分别测量时间—显存权衡。

| 候选 | 实验目的 |
| --- | --- |
| 当前配置 | 提供可恢复、可复测基线 |
| 仅减少模块 A 的重计算 | 测 A 用显存换速度是否值得 |
| 仅减少模块 B 的重计算 | 分离模块成本 |
| 验证过的联合配置 | 检查预算竞争和交互影响 |

重计算前后需保持语义；随机操作、状态更新和全局条件变化都需检查。
不要无条件关闭 RNG 状态保护；使用所装版本支持的 checkpoint 选项并记录选择。
前向与重算行为不同可能改变梯度，不能只用一次前向作为验收。

## 重新分配释放的显存

释放显存后比较减少昂贵重算、增加合法微批、增加有效预取三种方向。
三者竞争预算，组合后重测，不把单项收益简单累加。
增大微批且减少累积时，除全局批乘积外继续核对损失和随机/批次相关语义。
输入裁剪、分组或 allocator 改变后，原有重计算配置可能已不是合适工作点。
为最长输入、通信缓冲、验证/保存和长时间运行留出实测余量，不以占满为目标。

## 验收与交付

保留配置必须同时满足：暴露等待或更新耗时有收益、预算可持续、数值与质量通过。
使用代表性边界输入和周期操作复测，不只测试平均 batch。
记录每 rank 的耗时和峰值；任何 rank OOM/提前退出都使该组合不合格。
交付通信分组、预取深度、重算边界、批次组织、显存峰值和恢复回归结果。
硬件不足以验证多卡时明确标记待运行项目，不能用单卡结果替代分布式通过。
