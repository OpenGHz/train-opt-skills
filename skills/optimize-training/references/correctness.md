# 正确性与跨实现数值对齐

在迁移框架、改变精度/算子后端、裁剪输入、重构 attention 或优化器时使用本页。
目标是建立可信的训练语义和回归证据，再以修复后的实现作为性能基线。
本页是 v2 指南的执行摘要；各检查是工程建议，不代表已复现某个模型实验。

## 开始前准备

保存参考实现的提交、配置、依赖、权重哈希，以及候选实现的对应信息。
固定原始样本和最终模型输入；同时保存标签、mask、位置索引、噪声、时间变量、增强参数。
单步测试直接复用初始参数与随机输入，不要求不同框架凭相同种子生成相同值。
写明 train/eval 模式、梯度累积、损失归一化、裁剪与优化器状态。

| 改动类别 | 允许的结论 |
| --- | --- |
| 修复实现或恢复参考语义 | 报告修复及对齐结果；旧错误实现不能充当等价优化基线 |
| 系统实现优化 | 正确性通过后，在同一训练协议下比较性能 |
| 减少有效观测、分辨率、序列长度或改变全局批大小 | 作为训练方案变化，另做任务质量对照 |

## 预先约定通过标准

分别声明逐位一致、容差内一致和任务质量不劣化；三者不能互相替代。
按比较张量的精度、尺度和敏感性设置 `atol`、`rtol`，不要套用通用阈值。
数值判据可使用 `abs(candidate-reference) <= atol + rtol*abs(reference)`。
先单独检查 NaN/Inf，再记录最大绝对误差、相对误差分布和超阈值比例。
参考值接近零时相对误差不稳定，应结合绝对误差解释。
提前定义任务指标的允许退化、训练种子和评估场景，避免事后改门槛。

## 逐层定位第一处分歧

1. 核对权重映射、最终输入和所有 mask/位置索引。
2. 比较视觉 stem 或输入投影的输出。
3. 在每个重复块检查 attention、归一化、FFN 边界。
4. 比较输出头、逐样本或逐 token 损失及聚合分母。
5. 比较对应的输入梯度、参数梯度与裁剪结果。
6. 执行一次优化器更新，比较参数和优化器状态。
7. 对修复后实现补充短程训练与目标任务评估。

找到最早超出容差的边界后，保存其实际输入，单独复现该模块。
每修复一处重新跑整条链路；多个误差可能相互抵消，末端接近不能证明中间正确。
不要预设误差会同号、单调放大，或必然源于低精度。

## 数值路径检查表

| 模块 | 必查语义与精度 |
| --- | --- |
| GELU / 门控 FFN | 精确或近似形式、门控顺序、输入输出 dtype、对应梯度 |
| Attention | Q/K/V 轴、head/group 映射、缩放位置、mask 约定与广播、累加及 softmax 精度 |
| RoPE | 配对布局、位置偏移、频率与三角函数精度、旋转与降精度边界 |
| RMSNorm / 条件归一化 | epsilon、归约维度、scale 参数化、条件分支、输出转换 |
| 视觉 stem / 位置嵌入 | 卷积或线性布局、相加顺序、计算与入口 dtype |
| 更新链路 | 参数存储、梯度、归约、主权重及优化器状态 dtype |

“BF16 模型”不是完整精度说明：记录 autocast、显式 cast、matmul/convolution 后端策略。
AMP 按算子选择精度；单看张量 dtype 或添加 `.float()` 不足以证明内部路径。
`set_float32_matmul_precision("high")` 是 FP32 matmul 内部策略，不控制卷积。
JAX GELU 的文档默认是 `approximate=True`；检查参考模型是否显式覆盖，而非推断框架惯例。
保留可检查的参考路径，再逐项恢复混合精度、融合和编译；每项都重复回归。

## 结构语义与初始化

先写 token 可见关系，再审查实现，特别是视觉语言前缀和动作 token。
核对拼接顺序、各段长度、位置偏移、mask 广播和拆分后的专家/投影映射。
测试不等长序列、padding、缺失模态及实际支持的 head 配置。
若协议禁止前缀读取动作输入，固定随机状态后改变动作，前缀输出应在容差内不变。
这类不变性测试只用于模型明确规定的可见性，不能推成通用规则。

把参数分为完整恢复、实际新建、显式重置三组。
对后两组记录分布、fan-in/fan-out、缩放、截断和 bias；对齐时复用同一初始张量。
固定标准差 normal 与依赖 fan-in 的初始化不能因为同属正态分布就视为一致。
微调也要检查新增头和适配器；完全覆盖初始化仍可能改变后续随机状态。

## 决策与交付

| 证据 | 动作 |
| --- | --- |
| 输入或权重不一致 | 停止性能归因，先修复数据/映射 |
| 首个模块边界超容差 | 缩小到局部输入与数值路径，保留参考实现 |
| 单步通过但短程漂移 | 检查随机状态、优化器、归约、累积和数据消费顺序 |
| 短程 loss 接近 | 仅报告短程证据，等待任务质量门槛通过 |

交付参考契约、固定夹具、比较点/阈值、首处分歧记录、修复提交和质量评估结果。
对无法运行的 GPU/多卡测试写明“未验证”，并列出执行条件；不得标为通过。
