# 编译、融合与运行时调优

在计算热区、频繁小算子、图中断、重编译或优化器/日志同步占比高时使用本页。
每项开关都是待验证候选；成功开启不是性能完成证明。

## 基线与实验范围

固定语义、输入分布、精度、优化器、日志/评估/保存频率。
保存依赖、后端、编译器版本和启动命令；先建立前向、梯度、更新回归。
从占比高、重复调用、输入输出明确的区域开始，避免一次改完整训练程序。
不要同轮混改精度、损失、attention 后端和编译范围，除非明确标出不可拆依赖。
有跨框架对齐问题时，先以易检查路径建立可信实现，再恢复高性能路径。

## torch.compile 证据表

| 问题 | 要保存的证据 |
| --- | --- |
| 是否覆盖目标热区 | 编译前后轨迹、实际调用路径 |
| 是否频繁图中断 | 中断位置、原因及其必要性 |
| 是否频繁重编译 | 形状、控制流、guard 变化与重编译次数 |
| 启动成本能否摊销 | 冷启动/编译耗时和稳态每更新耗时 |
| 是否改变数值或内存 | 输入、前向、梯度、更新检查与峰值显存 |

保留能复现问题的代表性形状和控制流，而非只测一个固定 batch。
预热覆盖常见形状，但不能把真实作业里的重复编译成本从总耗时删除。
动态输入比较少量稳定形状分组与动态形状编译；保持有效内容和采样协议。
不能仅为消除重编译丢弃有效观测或更改有效序列长度。
输入裁剪、组批和编译相互影响，应在单项结果后增加小型联合对照。

## 编译的保留条件

粗估净节省为 `后续更新次数 × 每次更新节省时间 − 额外编译时间`。
估算要求后续性能稳定；频繁重编译应计入全部额外成本。
短作业可能稳态更快但总作业更慢，必须分别报告两者。
候选须同时通过数值门槛、任务质量、代表性形状、显存与完整作业验收。
失败时保留可回滚 eager 路径，写明不支持的形状或操作，不静默降低语义要求。

## 混合精度与融合后端

记录参数存储、autocast、局部显式转换、归约和优化器状态 dtype。
融合 attention 检查 Q/K/V 轴、head/group、mask、缩放和 softmax/cast 边界。
精度模式不能只记“BF16”；FP32 matmul 的内部策略也不自动控制卷积。
数学表达式相同不保证逐位一致，按预先约定的张量容差和质量门槛验收。
若误差超限，定位首个模块分歧；不通过放宽所有阈值让候选进入性能比较。
精确 GELU、显式 einsum、全 FP32 或某融合核均不是跨项目默认最优配置。

## 优化器实现

按安装版本确认逐张量、`foreach`、`fused` 的设备、dtype 和其他支持条件。
保持参数组、学习率、weight decay、epsilon、动量、梯度裁剪和更新顺序。
对同一初始参数、梯度和状态比较一次更新后的参数及优化器状态。
继续检查短程行为、保存和恢复；能运行不等于等价。
比较峰值显存与端到端时间，有些实现会增加中间内存。
若优化器只占关键路径很小部分，用收益上限决定是否继续投入。

## 日志、同步与周期操作

查设备张量打印、`.item()`、D2H、依赖设备结果的 Python 分支是否导致主机等待。
按已约定频率聚合日志，保留必要异常检测，测真实同步减少。
评估和保存单列成本；候选不能悄悄少做这些工作后宣称等价加速。
不同运行的缓存状态应披露，区分冷启动与热缓存。
垃圾回收、预取、allocator 等运行时项逐项评估，不默认关闭 GC 或周期清缓存。
只有可重复收益、可观测性保留且维护成本合理，才长期保留配置。

## 依赖与补丁治理

优先显式配置、受控适配层或局部替换，保留清楚的第三方边界。
确需分叉时锁定上游版本，为每项差异记录原因和回归覆盖。
不要在安装时静默覆盖第三方源码；临时补丁应检查目标版本和实际生效状态。
自包含实现是治理选择，不代表必须重写框架或第三方实现必然不正确。
升级依赖后跑数值、数据和转换回归；只检查 import 成功不够。
记录编译/融合的已知限制与关闭方法，确保他人可以复现并回滚。

## 决策与交付

| 结果 | 结论 |
| --- | --- |
| 稳态快、总作业慢 | 仅在足够长作业或复用条件下考虑保留 |
| 释放显存但暂不提速 | 标为资源收益或后续使能，不能写成直接加速 |
| 收益小于运行噪声 | 增加有针对性的重复或标证据不足 |
| 质量、边界形状或恢复失败 | 回滚，保留失败证据供后续定位 |

交付热区选择理由、图中断/重编译记录、冷/稳态测量、回归、配置和回滚开关。
未在目标 GPU 上运行的编译或 fused 候选只能写“待验证”。
